# IoT Dashboard API Reference

## Base URL
```
http://localhost:8080/api
```

## Authentication

### Device Authentication
Devices use JWT tokens obtained during pairing.

Header:
```
Authorization: Bearer <device_token>
```

### User Authentication
Web dashboard users use JWT tokens obtained after login.

Header:
```
Authorization: Bearer <user_token>
```

## Endpoints

### Device Pairing & Management

#### POST /devices/pair
Pair a device using a 6-digit code generated by the user.

**Request:**
```json
{
  "code": "123456"
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "device_id": "uuid",
    "access_token": "jwt_token",
    "refresh_token": "refresh_token",
    "expires_in": 86400
  }
}
```

**Error Responses:**
- 400: Invalid or expired pairing code
- 500: Server error

---

#### POST /devices/token/refresh
Refresh device access token using refresh token.

**Authentication:** Device token required

**Request:**
```json
{
  "refresh_token": "your_refresh_token"
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "access_token": "new_jwt_token",
    "expires_in": 86400
  }
}
```

**Error Responses:**
- 401: Invalid refresh token
- 403: Device not paired
- 404: Device not found

---

#### POST /devices/data
Submit sensor data from device.

**Authentication:** Device token required

**Request:**
```json
{
  "temperature": 22.5,
  "humidity": 45.2,
  "co2": 650
}
```

**Response (201 Created):**
```json
{
  "success": true,
  "data": {
    "id": 12345,
    "time": "2025-01-23T10:30:00Z",
    "temperature": 22.5,
    "humidity": 45.2,
    "co2": 650
  }
}
```

**Notes:**
- All sensor fields are optional
- Automatically updates device `last_seen` timestamp
- Device considered "online" if last_seen < 30 seconds ago

**Error Responses:**
- 401: Invalid or expired token
- 403: Device deleted/unpaired (device should re-pair)
- 500: Server error

#### PUT /user/devices/:id
Update device settings.

**Authentication:** User token required

**Request:**
```json
{
  "device_name": "Kitchen Sensor",
  "is_active": true
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Device updated successfully"
}
```

**Notes:**
- All fields are optional
- Only updates provided fields

---

#### DELETE /user/devices/:id
Delete/unpair a device.

**Authentication:** User token required

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Device deleted successfully"
}
```

**Notes:**
- Device will receive 403 Forbidden on next data POST
- Device should automatically re-pair when deleted

---

#### GET /user/sensor-data
Query sensor data.

**Authentication:** User token required

**Query Parameters:**
- `device_id` (optional): Filter by device UUID
- `start_time` (optional): Start timestamp (RFC3339)
- `end_time` (optional): End timestamp (RFC3339)
- `limit` (optional): Max results (default: 100)
- `offset` (optional): Pagination offset

**Example:**
```
GET /user/sensor-data?device_id=uuid&limit=50&offset=0
```

**Response (200 OK):**
```json
{
  "success": true,
  "data": [
    {
      "id": 12345,
      "time": "2025-01-23T10:30:00Z",
      "temperature": 22.5,
      "humidity": 45.2,
      "co2": 650
    }
  ]
}
```

## Device Failure Handling

When a device encounters persistent failures, it should automatically re-pair:

### Failure Scenarios

1. **403 Forbidden** - Device deleted/unpaired
   - Clear all tokens from NVS immediately
   - Return to pairing mode

2. **401 Unauthorized** (token expired)
   - Attempt token refresh using POST /devices/token/refresh
   - If refresh fails 3 times consecutively, re-pair

3. **Network/Connection Errors**
   - Increment failure counter
   - If counter reaches 10, clear tokens and re-pair
   - Reset counter on successful data transmission

### Re-pairing Process

1. Clear device tokens from NVS
2. Keep WiFi credentials (don't clear)
3. Show "Enter Code" screen on device
4. User generates new code on dashboard
5. User enters code on device
6. Device calls POST /devices/pair
7. Store new tokens in NVS
8. Resume normal operation

## Database Schema

### Tables
- `users` - User accounts
- `devices` - ESP32 devices paired to users
- `device_tokens` - JWT tokens for device authentication
- `pairing_codes` - Temporary 6-digit pairing codes
- `sensor_data` - Time-series sensor readings

### Device Online Status
A device is considered "online" when `last_seen > NOW() - 30 seconds`

### Security
- Row Level Security (RLS) enabled for user data isolation
- Password hashing using bcrypt
- JWT tokens with expiration
- Refresh tokens stored as SHA256 hashes
